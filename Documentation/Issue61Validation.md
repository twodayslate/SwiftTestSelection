# Issue #61: private extension helpers with scoped locals

Added XCTest entries and repeated plain extension headers were supported by #63. This change supports the scrolling-helper body, but **does not establish the proposed 46-UI real-app selection**. Replaying both original comparisons exposes a further caller boundary: XCTest failure formatting of `Optional<String>`. That boundary remains conservative.

## Implemented boundary

Immutable locals are checked in lexical order within each branch/loop. Their names and attachment provenance are discarded when that scope ends, and initializers are checked before their names become visible. Shadowing, pattern bindings, mutable locals, closure escapes and missing compiler evidence remain unsupported. The supported `for` form is an ignored element over a literal integer range. Explicit local annotations and cast types are limited to the built-in/XCTest value types already audited at both revisions; arbitrary aliases and compound types retain fallback. Default literal-type aliases are also audited, since an apparently primitive literal can invoke a project initializer at base.

The helper's callers, primitive default-argument thunk, assertion closures, transitive callees and receiver origins still require compiler evidence. Exact CoreGraphics rectangle operations and XCTest coordinate/drag signatures now have explicit contracts. Project overloads, SDK module collisions, ambiguous methods, shared/lifecycle effects and unknown external operations retain fallback. Changes to existing helper bodies must still preserve earlier statements and their control-flow context. Every allowed bare global participates in the reserved-name audit across head, base, and unowned base sources. This rejects historical rebinding of `max`, `CGRect`, and `CGVector` even when the project overload disappears before the head capture. Actor type names participate in the same audit as other nominal declarations: a synchronous, state-mutating actor initializer cannot be mistaken for a standard constructor or function when the actor disappears at head. Nested, distributed, and inactive conditional actor declarations are included. The audit also covers every component of accepted qualified types, trusted SDK module names, and `MainActor`. A cross-file alias for `Swift`, `XCTest`, or `MainActor` cannot silently redirect an accepted type or annotation to foreign code at base. The reserved-name audit derives the complete caller type vocabulary from the receiver contracts, including literal metatypes, generic value types, and receiver types. Historical aliases such as `UInt` and `URL` therefore cannot hide state-mutating caller initializers behind a safe head binding. Prefix, infix, and postfix operators are collected across the transitive helper body. Matching project implementations or precedence declarations in the helper module, or in unowned base files, prevent isolation at either revision; missing operator evidence also retains fallback. Literal bounds alone do not prove a range operator belongs to Swift. String interpolation's implicit initializer, literal-append, and interpolation-append calls participate in the historical member audit.

Historical binding checks also follow the compiler-checked caller closure, including test entries, lifecycle roots, closures, defaults, and transitive producers. Source units retain operator, member, subscript, constructor, interpolation, and bare-global uses. The audit checks corresponding historical units and declarations in head, base, and unowned base sources; historical storage and lifecycle declarations also cover synthesized initializer locations. Ordinary source functions and method overrides require an exact body in the checked closure at each revision, preserving supported static SDK factories and lifecycle implementations. Base-only overloads, storage/alias bindings, and missing use/declaration evidence retain fallback. Existing failure diagnostics take precedence when the helper proof has already failed. Unused competing range, interpolation, and `min` overloads retain focused selection in the control fixtures. Project receiver types used by the checked closure also require historical member proofs, including explicit and unqualified calls, implicit `callAsFunction`, initializers, and labeled subscripts. Source units retain their declared member names so each competing implementation is checked, including when the receiver use disappears at head. Bare references also participate in member binding checks, covering implicit-self property reads and method values. Stored-property initializer evidence is explicit: historical initializers on audited owners must match source validated by the successful head compiler-effect walk. A synthesized constructor located at its type header can authenticate unchanged initializers only when neither revision declares an explicit constructor. Changed/deleted initializers and constructor uses removed at head retain fallback. Missing initializer evidence retains fallback. Existing private-helper edits can reuse their validated statement-preservation proof after the current caller closure passes compiler-effect analysis.

Source declaration inventories also require explicit completeness evidence. Unexpanded freestanding macros, attached macros, unknown attributes, and legacy metadata prevent private-helper isolation across head, base, and unowned base sources. This protects generated operators, globals, members, and callbacks, even when the macro appears outside the changed helper or disappears before the head capture. Recognized compiler attributes and bare source-location literals remain supported; a `MainActor` attribute additionally requires trusted imports. Compiler-effect analysis continues where possible to retain more specific failure diagnostics.

Private-helper proof version is 21 and the module-fragment cache is version 26. Older saved helper proofs cannot grant this isolation.

The five requested boundaries are covered: #63 supplies extension-entry and repeated-header support; this PR supplies the scoped helper body and exact unsupported-effect diagnostic, conservative fallback with compiled positive/negative fixtures, and both original scope-local capture replays. ## Historical comparisons and remaining effect

The replay reuses the two complete single-head-build SIL captures documented in [the prior validation](PrecisionTickets60-62.md). Each contains ten modules, a normalized complete test plan and complete UI mappings. No new application build, base compilation or compiler replay was performed. All current source proofs were regenerated from the retained source export; source keys and semantic fingerprints were checked unchanged. Compiler edges, inventory and products were untouched.

Each scope contains only `ChainOfCustodyUITests/NotificationUITests.swift` and excludes the same six independently executed entries recorded in the issue. The helper's former nested-local rejection is gone. Both scopes retain the known scrolling-helper caller and fall back on this exact generic call:

```
$s6XCTest14XCTAssertEqual___4file4lineyxyKXK_xyKXKSSyXKs12StaticStringVSutSQRzlF
substitutions: Optional<String>
```

The caller uses `XCTAssertEqual(comment.value as? String, "Read")`. Optional equality alone does not prove the failure-formatting path: a project can add `Optional: TextOutputStreamable`, whose witness can mutate shared state or replace an SDK implementation. A compiled negative fixture demonstrates that custom formatting body. No such harmful conformance is alleged in the consumer; the analyzer lacks a closed formatting proof and must keep fallback. This is a caller/receiver contract limitation, not evidence that the loop itself escapes.

The consumer's original version-2 tier policy was rerun with its 40-test Base configuration, original full-review candidate report, and refreshed scope result. The full production diff was not substituted for the scope-local proof.
